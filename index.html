定義說明
安裝來源
Google Ads install
Google Ads 後台以其內部歸因模型 ICM（In-Channel Measurement）認列的安裝數，包含 view-through attribution，數字通常偏高
AF SSOT install
AppsFlyer Single Source of Truth，與媒體端對帳去重後的歸因結果，通常低於 Google Ads
AF Classic install
AppsFlyer Classic（傳統歸因）認列的安裝數。與 AF SSOT 出自同一套 AppsFlyer，差別在於 SSOT 會與媒體端對帳去重、Classic 不會，因此 Classic 通常高於 SSOT。依日期與 campaign 對應；欄位可放在 af_ssot.csv（欄名 mkt_install 或 mkt_installs 皆可），或同資料夾中獨立的 mkt_backend.csv，兩者並存時以 af_ssot.csv 為準
為什麼會有第三條線

三條線分別是「媒體端說的」（Google Ads install）、「歸因工具去重後說的」（AF SSOT install）與「歸因工具未去重說的」（AF Classic install）。三方同框，才能看出落差究竟來自 Google 與 AppsFlyer 的歸因模型差異，還是來自 SSOT 去重本身。數字本來就不會完全相同，重點在於走勢是否同步；某一條線單獨偏離時，問題多半就出在那個來源。

整天算不算數：全有或全無

某天若有 4 支活動在跑，AF Classic 只回報其中 3 支，系統會把整天視為資料不完整而斷線，不會只把那 3 支加起來。原因是：少掉一支大活動的加總會畫出一個看起來很像「量崩了」的深谷，比直接留白更危險。所以規則是全有或全無——當天在跑的活動全部都有數字才計入。也因此，篩選單一活動或單一地區時，可用天數通常會比「全部」時更多。

空白與 0 的差別

AF Classic 某天沒有提供資料時，系統記錄為空值而非 0：圖上斷線、表格與卡片顯示「—」。若真的是當天零安裝，才會顯示 0 並把線畫到底。這個區分是刻意保留的，避免把「沒資料」誤讀成「量掉光了」。

走勢背離程度（pp）

pp（percentage points，百分點）是衡量兩個來源「走勢差多少」的單位。例如 AF 今日比昨日漲 20%、Google 漲 15%，兩邊差 5pp。數字越小代表兩邊越同步；數字突然拉大，建議確認是否有 SDK 版本更新或歸因異常。

常見原因

Google ICM 通常高於 AF SSOT，主要來自歸因視窗不同、view-through attribution、跨裝置識別差異。若差異率突然異常升高，可能是 SDK 版本更新或 iOS 隱私政策變更所致。
